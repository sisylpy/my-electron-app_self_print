## 2026-09-02：商品客户分布改为右侧抽屉

### 界面调整

- 商品明细行和行尾箭头均可打开右侧客户分布抽屉；不再在商品长表格底部展示客户详情；

- 抽屉下方按销售额贡献逐家展示客户，包含贡献条、销售金额、数量、平均单价、订货日数和最近成交日期；

### 数据与边界

- 商品客户明细的桌面白名单和服务端单次返回上限由 20 家提高到 200 家，以覆盖正常业务下的逐家分布；
- 超过 200 家时仍保留“其余客户”合计，避免极端数据量造成超大响应；
- 本次没有改变销售金额、数量、平均价、历史订单事实表和父客户去重口径。

## 2026-09-02：完成销售分析 V1 正式实现

### 服务端

- 新增 `com.nongxinle.distribute.analytics.sales` 只读分析包和 MyBatis 扫描；没有数据库迁移；
- 新增概览、大类下钻、商品重要客户三个正式接口，统一使用桌面安全会话中的配送商身份；
- 新增权限 `analytics:sales:read`，当前只授予配送商管理员；
- SQL 唯一事实表为 `nx_department_order_history`，没有查询 `nx_department_orders`；
- 分类通过配送商品关联当前 `nx_distributer_father_goods`，返回 `CURRENT_CATALOG_FALLBACK`；
- 金额使用历史 `nx_DO_subtotal`；数量优先有效 `nx_DO_weight`，否则回退 `nx_DO_quantity`，并始终按 `nx_DO_standard`/商品单位分组；
- 加权平均价只使用存在有效数量的成交金额除以同单位数量；无有效数量的金额保留在成交销售额中，但不污染平均价；
- 客户按照 `nx_DO_department_father_id` 聚合；商品重要客户返回 Top 5 和“其余客户”合计。

### 桌面端

- 新增“经营分析 → 销售分析”，路由 `/sales-analysis`，模块权限 `salesAnalysis`；
- 页面支持近 7/30/90 天与自定义日期（单次最多 90 天），展示概览、大类分布、客户贡献、小类列表、商品表和重要客户；
- 销售分析请求通过 Electron 主进程白名单发送，渲染层不接触 Bearer Token，也不能提交配送商 ID；
- 商品明细按单位显示销售数量和加权平均单价，不把斤、箱、个、瓶强行相加。

### 验证

- 服务端定向测试：`SalesAnalysisQueryServiceTest`、`SalesAnalysisReadMapperContractTest`、`DesktopDispatchPermissionServiceTest`、`DesktopDispatchAuthInterceptorTest`；
- 桌面 presentation 定向测试通过；
- `scripts/security-smoke.js` 通过，确认销售分析使用只读白名单网关；
- Vue 生产构建通过；现有 Bills 动静态导入和大分包提示仍为项目原有构建警告。

### 后续修改禁止回退的边界

- 不得为了“实时”把未完成的 `nx_department_orders` 混入销售额；
- 不得跨单位合并数量或平均价；
- 不得让页面传入 `disId` 或绕过主进程白名单；
- 不得把当前目录回填结果描述成历史分类快照；
- 接入销售退货净额前，页面继续使用“成交销售额”，不能改称“净销售额”或“毛利”。
