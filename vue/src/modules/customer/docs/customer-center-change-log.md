## 2026-09-02：恢复客户商品“订货单价”入口

### 问题与决定

- 客户商品操作区原来只显示“商品要求”和“历史单价”，桌面端遗漏了已有的客户订货单价维护功能；这不是按钮被 CSS 隐藏，而是模板中没有渲染该入口。
- 操作区恢复为“商品要求”“订货单价”“历史单价”三个按钮，并同时适配宽屏和窄屏换行。
- “订货单价”维护 `nx_department_dis_goods.nx_DDG_order_price`，作为该客户以后订货时的默认价格；“历史单价”继续只读已完成历史订单的成交记录，不能用历史明细代替当前默认价。

### 接口与交互

- 客户商品轻量画像增加 `orderPrice`，只返回当前客户商品关系的默认订货单价，不改变订货金额、频率、平均数量和历史单价的计算口径。
- 保存继续复用既有 `POST /api/nxdepartmentdisgoods/updateDepGoodsSellingPrice`，桌面端只提交关系 ID 和新单价，不覆盖配送要求或订货商品名称。
- 点击“订货单价”打开独立编辑弹窗，预填当前价格；只接受大于 0、最多 4 位小数的价格。保存成功后重新读取客户商品画像，使当前列表显示与服务端保持一致。

### 回归保护

- 桌面回归锁定三个操作按钮、订货单价弹窗、保存接口和画像 `orderPrice` 映射。
- 最终测试、构建和界面验收结果记录在本条“验证”中。

## 2026-09-02：两种客户商品统计增加平均每次订货量

### 需求

在“订货频率”和“订货金额”两种客户商品统计中，都显示该商品平均每次大约订多少，帮助配送商同时判断订货节奏和常用数量。

### 数据口径

- 只读取已配送完成并进入 `nx_department_order_history` 的历史订单商品行；当前 `nx_department_orders` 中未完成的新订单不参与平均。
- “每次”按一条已完成历史订货商品记录计算，平均字段使用历史订货数量 `nx_DO_quantity`。
- 只纳入大于 0、可转换为数字，并且历史订货单位 `nx_DO_standard` 与客户商品当前订货单位一致的记录；不同单位不能混算。
- 客户商品当前单位依次取客户订货单位、客户商品标准单位、配送商品标准单位。没有一致单位或有效数量时返回空值，桌面端显示“平均每次 暂无数据”。
- 历史缺少客户商品关系 ID 时，继续沿用“部门 + 商品归入最早规范关系”的既有规则，避免同一历史订单被重复平均。

### 时间范围与显示

- 订货频率视图固定显示近 90 天平均订货量，与该视图的频率统计窗口一致。
- 订货金额视图跟随所选的近 30 天、近 90 天、近一年或全部历史范围。
- 平均数量最初显示在商品名称和规格下方；后续已按上方布局决定移入独立订货习惯列，两种视图继续共用同一平均数量口径。

### 接口字段

`GET /api/nxdepartmentdisgoods/disGetDepGoodsProfile/{depFatherId}` 的每个商品新增：

- `averageOrderQuantity30Days`
- `averageOrderQuantity90Days`
- `averageOrderQuantity365Days`
- `averageOrderQuantityAll`
- `averageOrderQuantityUnit`

字段由现有客户商品画像查询直接聚合，无新增数据库表或迁移。

### 回归保护

- 服务端 Mapper 回归锁定四个时间窗口、数量与单位来源、单位一致比较，以及不得读取当前订单表。
- 桌面端展示回归锁定：频率视图使用近 90 天平均量，金额视图跟随所选时间范围，零值显示无数据，并保留商品行中的平均数量展示。
- 最终测试和构建结果记录在本条“验证”中，避免以后修改时丢失上述口径。

### 验证

- 服务端 `NxCustomerGoodsProfileMapperXmlTest`：2 项通过；验证 Mapper 可解析、四个平均数量窗口、数量与单位来源、单位一致比较，以及当前订单表继续被排除。
- 桌面端 `customerGoodsAmountPresentation.test.mjs` 和 `customerGoodsPanelLayout.test.mjs`：均通过；覆盖频率视图固定近 90 天、金额视图跟随范围、零值无数据和商品行展示绑定。

## 2026-09-02：修复频率/金额切换按钮被搜索框遮挡

### 现象与原因

- 宽屏客户中心中只露出一小段“订货频率”按钮，“订货金额”按钮无法点击。
- 点击事件本身有效；原因是右侧工具栏空间不足时，Flex 布局允许切换控件横向收缩，而控件又设置了裁剪，导致第二个按钮被搜索框遮住。

### 修复

- 切换控件和时间范围控件禁止收缩。
- 两个切换按钮各自保留固定的最小点击宽度，确保文字和点击区域完整。
- 顶部概览允许弹性占位，空间不足时整组工具栏换行，不再互相覆盖。
- 小屏仍允许工具栏内部换行，搜索框独占一行。

### 回归保护

- 增加 `customerGoodsPanelLayout.test.mjs`，锁定按钮不可收缩、最小点击宽度和“订货金额”点击绑定。
- 布局回归测试和原金额分档测试均通过。
- 本地浏览器按客户中心同宽工具栏实际验收：两个按钮均完整可见，宽度各 79px；第二个按钮右边界为 917px，搜索框从 926px 开始，两者没有覆盖；实际点击后激活项变为“订货金额”。
- 桌面端生产构建通过，Vite 完成 696 个模块转换。

## 2026-09-02：客户商品增加订货金额视图

### 需求

客户商品原来只按订货频率分组。增加按订货总金额查看的方式，用于识别对客户营业额贡献最高的商品，同时保留原有频率视图。

### 产品决定

- 默认仍为“订货频率”，避免改变已有使用习惯。
- 顶部增加“订货频率 / 订货金额”切换。
- 金额模式默认统计近 90 天，并支持近 30 天、近一年和全部历史。
- 金额不是按固定人民币门槛分档。不同客户规模不同，固定门槛会失真，因此按当前客户全部商品在所选时间范围内的累计金额贡献分组：
  - 核心商品：累计贡献开始位置低于 70%；
  - 重要商品：累计贡献开始位置为 70%–90%；
  - 一般商品：累计贡献开始位置达到 90% 以后；
  - 无订货额：所选时间范围内没有已完成订单，或商品小计为空、非数字、零或负数。
- 使用“商品开始贡献前的累计占比”决定档次。即使第一种商品单独超过 70%，它仍属于核心商品，核心档不会为空。
- 金额组内按订货金额从高到低排序；金额相同时按最近订货时间、商品名称排序。
- 每行显示精确订货金额和占客户所选范围总额的比例，继续保留上次订货时间、商品要求和历史单价入口。
- 商品搜索只过滤已经完成分档的结果，不以搜索子集重新计算占比和档次。

### 数据口径

- 唯一事实来源：`nx_department_order_history` 中已完成的客户历史订单商品行。
- 金额字段：历史订单商品小计 `nx_DO_subtotal`，不是配送商采购成本。
- 当前尚未配送完成、仍在 `nx_department_orders` 的新订单不参与金额、频率、上次订货日期或近 30/90 天统计。
- 负数、空字符串和无法形成有效正金额的小计按 0 处理；所选范围合计为 0 的商品进入“无订货额”。
- 统计仍以客户部门商品关系为单位；历史缺少关系 ID 的订单沿用既有“部门 + 商品归入最早规范关系”的规则，避免重复累计。

### 接口字段

`GET /api/nxdepartmentdisgoods/disGetDepGoodsProfile/{depFatherId}` 的每个商品新增：

- `orderAmount30Days`
- `orderAmount90Days`
- `orderAmount365Days`
- `orderAmountAll`

字段均来自同一次客户商品画像查询，没有新增数据库表或迁移。

### 主要修改

- 服务端客户商品画像查询增加四个时间窗口的历史订货金额聚合。
- 服务端轻量响应增加四个金额字段。
- 桌面端客户商品页增加显示方式切换、金额时间范围、金额概览和 ABC 贡献度分组。
- 金额分档提取为独立展示函数，并增加边界回归测试。

### 验证

- 服务端 `NxCustomerGoodsProfileMapperXmlTest`：2 项通过，验证 Mapper 可解析、金额只来自历史订单，并锁定四个金额窗口与客户商品关系归属。
- 桌面端 `customerGoodsAmountPresentation.test.mjs`：通过，覆盖金额降序、70%/90% 边界、零金额分组和单一大额商品边界。
- 桌面端生产构建：通过，Vite 完成 696 个模块转换。
