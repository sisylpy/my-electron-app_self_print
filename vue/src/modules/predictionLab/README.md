# Prediction Lab 前端边界

> 阶段状态（2026-08-22）：可信采购助手第一阶段完成。桌面端进入 `Shadow Mode`，日常入口固定为 `V8_REPLENISHMENT_STATE`；V9 未登记，历史算法比较与 V9 Candidate 研究仅作为服务端/脚本复现资产保留，不再作为桌面日常入口。

## 职责

- 以“商品采购建议”产品页展示商品级采购建议，不在客户界面重复显示产品宣传标题或研发术语；
- 中间栏完整展示可搜索门店目录，默认落在第一家有历史数据的真实门店，“全部门店”固定在目录首位；
- 采购时间、可信等级、汇总指标、商品大类和商品明细统一放在右侧工作区；
- 页面标题右侧的系统操作区承载常用日期、A/B 级切换和刷新操作，避免正文重复占用纵向空间；
- 页面沿用客户中心的全高工作区结构和主次字号；门店目录、商品大类及商品明细均在各自固定区域内滚动，不延长整个页面；
- 支持今天、明天、未来 7 天和最长 31 天的自定义范围；多日结果只在“商品 ID + 真实订货单位”同时一致时汇总；
- 商品大类和商品明细使用同一个主从工作区，不通过独立卡片或中间分隔线拆成两个模块；
- 产品页面只展示服务端 `/forecasts` 返回的真实只读建议，不读取冻结样本、不自行运行研究模型；
- 展示 V8 商品候选与服务端冻结 Prediction Policy Engine 给出的 A/B 级、可信度、理由和数量；
- C 级和 abstain 不进入主动建议；没有 A/B 时明确展示“当前没有达到可信门槛的商品”，不补假数据；
- 所有数量继续人工确认。

## 状态

实验目录、单次结果和筛选条件只保存在 `PredictionLab.vue` 内存状态中。历史比较服务与 API 适配器仍作为复现资产保留，但组件不再包含算法切换、比较页或“一键比较全部算法”。

本模块不建立 Vuex 全局订单副本，不写 `localStorage`，不读取或修改 `mcpPrintQueue`，不调用订单、采购、派单或打印写接口。

日常单日与多日建议统一调用服务端 `/forecasts`。D64 的 2026-08-22 现场 Shadow 快照仅作为验收复现资产保留，产品页面不再按配送商、门店或日期旁路到该固定数据。

## 服务端主权

前端不实现预测算法，不计算综合评分，不自行判断客户范围。所有预测、真实值读取、误差和指标都来自 `/api/purchase-prediction-lab`。

V6 页面只解释服务端分阶段输出，不在浏览器内修改门槛或重新计算候选。

V7 页面同样只展示服务端候选通道。篮子容量、通道融合和同行类型边界均由只读实验服务决定。

V8 页面不会在前端重算状态或关联，也不会把影子替代信号加入预测商品。影子结果只用于观察“若替换是否会改善”，正式候选仍完全来自服务端 V8 模型。

桌面端不会把离线 Partial Procurement Aggregation 结果伪装成实时采购总量。部分采购辅助与未知量台账目前保留在服务端冻结机器结果和报告中；在建立新的只读展示合同前，桌面端不自行拼接或重算这些数据。

Prediction Policy Engine 页面不在前端计算可信分或分级。产品运行时唯一来源是服务端 `/forecasts` 的
`item.policy`；字段缺失时商品不展示，禁止按 `confidencePercent` 补等级、补可信度或默认成 B 级。

多日采购页面同样不改变主权边界：多日资格和数量拆分均由单次服务端范围请求返回；前端不再逐日调用、
递推或自行拼接预测，也不会在不同 `standard` 之间换算数量。

`data/`、`policy/policyReplayAdapter.js` 和 `shadow/d64ShadowAcceptanceAdapter.js` 是历史 UX 验收与现场
Shadow 的归档复现资产。它们不得被 `PredictionLab.vue`、产品路由或生产 API 适配器导入；保留文件不表示
假数据仍可进入客户页面。
