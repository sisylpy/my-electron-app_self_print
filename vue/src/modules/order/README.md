# order 模块边界

## 订单工作台 V2

订单工作台是订单域后续演进的页面入口，当前包含两个明确场景：

- `AI 下单`：通过客户上下文创建订单，复用已经验证过的文字、图片、Excel 和手工录入能力；
- `今日订单`：按配送商读取今日待处理客户，再按客户读取服务端订单明细。

V2 不再由 `Bills.vue` 同时承担客户目录、录单、今日订单和历史订单。模块内部按以下边界组织：

- `services/orderWorkbenchService.js` 负责服务端数据读取与响应适配；
- `composables/` 负责客户上下文和今日订单收件箱状态；
- `components/workbench/` 只负责场景交互；
- `views/OrderWorkbenchV2.vue` 只编排页面，不复制订单业务规则。

图片识别、商品匹配、订单保存和订单编辑继续由现有订单组件及服务端规则负责。

旧 `/orders/intake` 路由保留用于对比；V2 使用 `/orders/workbench-v2`，验收后再切换正式入口。

## 调度只读边界

`order` 负责客户和订单领域的只读查询与展示适配。

Slice 1 仅新增客户目录 GET，用于按服务端客户 ID 补充调度站点地址。订单阶段、
未分配口径和配送状态仍全部来自 dispatch `pageViewModel`。

它不负责：

- 判断订单是否可派；
- 计算未分配订单；
- 修改派单状态；
- 直接操作打印模板。

本模块不导入、不改变现有 Bills 和打印流程。
