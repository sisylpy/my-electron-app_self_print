# 业务功能与用户操作规则

## 1. 适用范围

本章规定“读取微信订单”到“老板确认并保存正式订单”之间的产品行为。技术实现以 `OrderWorkbenchV2.vue`、`WechatOrderImportModal.vue`、`wechatOrderMessagePolicy.js` 和 Java 微信订单服务为准。

核心原则：微信消息是**订单来源候选**，不是正式订单。系统读取、去重并形成待确认任务；老板仍可编辑、删除非订单内容、解析商品并决定是否保存。

## 2. 微信账号、会话与客户绑定

### 2.1 身份模型

绑定同时包含：

- 配送商租户 `disId`。
- GrainPrint 客户 `customerId`。
- 当前微信账号的不可逆 `accountFingerprint`。
- 好友或群聊的不可逆 `conversationFingerprint`。
- 用户可见名称 `displayName`。
- 会话类型 `direct` 或 `group`。
- 群规则 `ALL_MEMBER_MESSAGES` 或 `MENTION_SELF_ONLY`。
- 递增的 `bindingRevision`。

原始 `wxid_*`、`*@chatroom`、数据库路径和密钥不得进入 Vue、Java 或日志。Reader 对外只返回 `fp:<hash>` 身份。

### 2.2 当前账号识别

Vue 通过 `window.electronAPI.wechatReader.listAccounts()` 取得账号候选，通过 Reader 的当前账号/参与者数据识别 `isSelf`。扫描具体会话时还会调用 `getSelfParticipant`（旧兼容路径可取全体 `getParticipants`）。无法确认当前账号或群内当前账号身份时，扫描应失败并提示用户，而不是猜测发送人。

### 2.3 好友、专属群和混合群

- **微信好友**：`conversationKind=direct`，不允许设置群规则。
- **专属群**：`conversationKind=group` 且 `groupMode=ALL_MEMBER_MESSAGES`。接收群内其他成员发送的可读文字和图片，排除当前账号自己发送的消息。
- **混合群**：`conversationKind=group` 且 `groupMode=MENTION_SELF_ONLY`。只接收明确 `@当前账号` 的可读文字，并在形成订单文字前移除该 @；图片本身不能证明 @ 关系，因此不自动归属客户。

混合群图片会以 `MIXED_IMAGE_NOTICE_PENDING` 登记并通过已有提醒方式呈现；确认提醒后变为 `MIXED_IMAGE_NOTICE_SHOWN`。它不自动生成正式订单，也不应绕过人工确认。

### 2.4 绑定、同名和重新绑定

客户中心保存微信关联时调用 V1 `PUT /customer-wechat-orders/{customerId}/binding`。Java 在当前租户内校验客户存在，规范化好友/群模式，并用 `(distributor, accountFingerprint, conversationFingerprint)` 唯一约束防止同一会话同时绑定两个客户。

同名好友或同名群不能仅凭显示名安全区分。当前 UI/自动扫描会把重名识别为歧义并要求人工选择或先改成唯一名称；真正的持久身份仍是账号指纹与会话指纹。未来不得退化为“只按名称绑定”。

当同一会话明确转绑给另一个客户时，服务端会清理旧绑定并提升绑定版本。已经生成正式订单的消息仍归原客户并继续参与全局去重；仅未完成的消息可跟随新绑定。核查时该语义有两项 Java 契约测试失败，修改绑定逻辑前必须先解决 [测试文档](./04-testing-and-operations.md) 中的待核实项。

账号切换、会话身份改变或重新绑定后，旧 `bindingRevision` 的扫描/保存请求必须被拒绝。显示名称改变不等于可以静默换身份；扫描前后的可见标题验证用来防止读错同名或已改名会话。

## 3. 当前用户操作流程

### 3.1 进入与选择客户

用户在订单工作台点击现有“读取微信订单”入口。系统打开微信订单弹窗并恢复服务端尚未完成的待确认任务。用户可：

- 读取/识别当前选中的微信会话。
- 扫描微信未读会话。
- “重新检查全部”已绑定且参与本次扫描的客户。
- 在扫描报告或任务列表中选择客户任务继续确认。

工作台使用 `showSelectedWechatConversation`、`refreshSelectedWechatConversation`、`readUnreadWechatOrders`、`scanAllBoundWechatOrders` 和 `restoreWechatDraftTasks` 组织这些操作。UI 必须验证实际可见会话标题；不能因为客户列表上的名称相同就直接把消息归属给客户。

### 3.2 读取当前会话

当前会话入口先取得可见微信标题/头像，匹配现有客户关联，必要时由用户确认客户，再由 `prepareWechatOrderImport` 读取 Reader 消息、过滤发送人和群规则、提交消息台账并领取任务。读取失败时保留已有任务，显示可重试错误；不得推进一个未完成扫描的游标。

### 3.3 扫描多个客户

“重新检查全部”加载客户中心已有微信绑定，逐个核验绑定、会话名称和消息。结果在巡查报告中分为可直接保存、需检查、无新订单或失败/警告。关闭报告后必须回到同一批待确认任务，而不是丢弃刚领取的任务。

### 3.4 自动扫描

自动扫描由现有 Electron 设置控制：

- 主进程 `src/wechat/auto-read-scheduler.js`。
- 配置文件：Electron `userData/wechat-auto-read.json`。
- 配置项：`enabled`、每日 `HH:mm` 时间列表、按配送商/客户控制的参与状态。
- 调度器每 15 秒检查一次，只允许一个活动 run，同一分钟不重复触发。
- 触发事件 `wechat-auto-read-trigger` 进入 Vue 后复用“扫描全部已绑定客户”的能力，结束时由 `wechat-auto-read-finish` 释放 run。

不得再创建第二套定时器，不得擅自改变用户已配置的时间、参与客户或关闭状态。

### 3.5 读取完成与失败

读取完成后，文字和图片按来源消息拆成独立可保存任务：

- 同一会话的一组文字形成文字任务。
- 每张不同原图形成独立图片任务。
- 字节完全相同的重复原图可合并为一个可见图片任务，但任务必须认领所有物理消息，保存后不能再次出现。

Reader 错误通过稳定错误码返回。绑定变化、同名歧义、原图未下载、服务端冲突等均应保留为可见错误/警告。系统不能把失败伪装成“没有新订单”。

## 4. 订单编辑、解析和确认

### 4.1 文字订单

筛选后的微信文字进入现有订单编辑区。老板可以：

- 直接修改数量、单位、商品名称等内容。
- 删除“到了吗”等与订单无关的聊天行。
- 使用现有“AI 协助解析订单”能力生成/调整商品行。
- 使用现有普通解析功能后继续人工确认。

系统不额外承担聊天意图分类，也不自动判断“加货”“减货”或“新订单边界”。这些语义由老板在现有编辑与确认流程中决定。

### 4.2 图片订单

好友和专属群图片先以附件引用进入台账。如果原图可恢复，进入现有图片识别/裁剪/解析流程；原图尚未下载时保持 deferred 状态并重试。混合群图片不自动归属，只提醒人工处理。

### 4.3 添加订单入口

当前 HEAD 已把顶部“+ 添加订单”作为统一手工下单入口，支持复制粘贴、图片识别、Excel 粘贴和手工录入。微信任务中的手工补充仍应复用同一个订单工作区和客户上下文；不得再建立平行的保存实现。核查时相关页面还有未提交增强，发布前必须以独立提交和测试确认最终 UI。

### 4.4 草稿和稍后处理

任务领取后保存在 `nx_department_wechat_order_task`，老板编辑后的 `draft_text` 通过带 `draftRevision` 的 PATCH 持久化。Electron 关闭或弹窗关闭后，下一次进入会查询 `tasks/pending` 恢复。

必须区分：

- **稍后处理/普通关闭**：保留 PENDING 任务和草稿。
- **回退任务（discard）**：任务变为 `DISCARDED`，消息释放为可再次领取状态；以后扫描可重新激活。
- **确认为非订单（ignore/移除任务）**：任务和消息变为 `IGNORED`，以后扫描不再拉回。

用户明确删除无关图片或聊天任务时，应走 ignore 语义；不能只从前端数组移除，否则下一次会重复出现。

### 4.5 保存正式订单

保存前，`wechatOrderSource` 必须携带客户、账号指纹、会话指纹、绑定版本、微信任务 ID 和精确消息指纹列表。Java 在任何订单写入前锁定并校验来源；文本保存成功后，在同一外层事务内把对应消息改为 `ORDER_CREATED` 并完成任务。任一状态数量不一致应让整个保存回滚。

老板未点击保存前，系统不得自动把候选任务当作正式订单。批量巡查中的“直接保存”也必须基于现有校验和用户触发，不能静默扩大自动保存范围。

## 5. 不可擅自改变的产品规则

现有用户操作流程原则上冻结。未经用户明确批准，后续 Agent 不得：

- 改变客户选择、微信切换、当前会话核验方式。
- 增加不必要的按钮、弹窗或额外确认步骤。
- 改变任务列表、巡查报告及确认页的基本关系。
- 改变人工编辑与 AI 解析的主从关系。
- 自动替老板确认、忽略、保存或合并正式订单。
- 把混合群图片自动归属给当前客户。
- 仅用显示名称替代账号/会话指纹绑定。
- 新建另一套自动扫描调度器，或覆盖用户已有时间配置。
- 因订单文字被编辑而改变消息指纹、账号指纹、会话指纹或绑定版本。
- 让“关闭弹窗”隐式等于 ignore 或正式保存。

若确实需要改变用户可见流程，必须先给出影响说明、原型/步骤和回退方案，取得用户明确批准后再修改。
